# Institution requirements

- The mobile app should have at least 3 features, and each team member should design and implement at least one feature. (The minimum number of features depends on the number of team members.)  
- The mobile app should have a minimum of 3 screens with appropriate navigation between them, for example, a home screen, a dashboard screen, and a settings screen.   
- Students can use an existing API, create their API using JSON server or other means, or manage the data using state and array inside the app.  
- Students who choose to use an API should use Fetch to interact with the API and display data on the screens.  
- Students who manage the data using state and array inside the app should use appropriate React Native components to display and update the data.  
- Students should use Async Storage to make the data persistent.   
- The application should allow CRUD (Create, Read, Update, Delete) operations on the data. For example, creating a new record, reading existing records, updating existing records, and deleting records.   
- The application should have a well-designed UI that is visually appealing and easy to use.   
- The team should submit their code on GitHub along with two “.md” files.  
- The team should use README.md to explain what the key features are, how the application works, and what they learned.  
- The team should create MEETINGS.md to show when each team has weekly meetings and what tasks each member worked on. Each team member must explain their own tasks.  
- The team should create MEETINGS.md to show when each team has weekly meetings and on what tasks each member worked. Each team member must explain their tasks.  
- The team is expected to deliver a report, a presentation, and a demo video, along with the mobile app.   

# Application Idea (Boulder Logs)

This is a mobile application that allows users to manage their growing process in indoor climbing. It acts as a diary, allowing them to capture images, videos, and notes of their boulder problems, track their progress, and set goals for improvement. The app will have the following features:

- Take images and videos of the boulder problem and save them in the app.
- Track the number of attempts and successful completions for each boulder problem.
- Set goals for improvement and track progress over time.
- Take notes on each boulder problem, including difficulty level, techniques used, and personal reflections.
- View a history of all boulder problems attempted, including images, videos, notes, and progress tracking.
- Allow users to create and manage a list of boulder problems.

# Architecture bullet points

1. The application will follow traditional mobile app architecture that has react native as the primary framework: Feature-based architecture
2. The application will be built using these main technologies: React Native for the frontend, Node.js with Express for the backend, MongoDB for the database, and AWS S3 for cloud storage.
3. The application will have a well-defined folder structure, with separate folders for components, screens, services, and utilities.
